# P17 · Отдельные копии салонов; сети, аренда и страны

PROMPT BEGIN P17
Реализуй подтвержденный режим SALON OS: отдельная Git-ветка и копия проекта для каждого салона. Не заменяй решение общей SaaS-инсталляцией. Отделяй конфигурацию и брендинг от местных изменений кода, чтобы обновления оставались управляемыми. Базовый шаблон помогает переносу исправлений и не отменяет выбранные ветки.

ОБЯЗАТЕЛЬНО В ПЕРВОМ РЕЛИЗЕ: реестр салон → репозиторий/ветка → версия кода → версия БД → версия конфигурации → примененные security patches. Новый экземпляр создается без чужих данных/секретов. Перенос одного исправления на разные ветки документирован и проверен. Для обновления нужны dry-run, совместимость, резервная копия, миграция и приемка; ошибка одного экземпляра не запускает миграции остальных. Устаревшая инсталляция видна оператору. Управление содержит версии/лицензии/здоровье, без общего хранилища посетителей; поддержка получает ограниченные права с аудитом.

СЛЕДУЮЩИЕ РАСШИРЕНИЯ — только при подтвержденной потребности. Для сети бизнес, филиал и юрлицо-продавец различаются. Общие стандарты допускают контролируемые местные цены, услуги, графики и правила. Передача клиента/материала/сотрудника учитывает права, доступность и реальную логистику. Сравнение учитывает специализацию, доступные часы, цены, возраст точки и состав расходов.

Аренда/коворкинг — отдельная модель: место, включенные услуги, арендатор, срок, стоимость, задолженность и совместные ресурсы. Оборот независимого мастера не становится выручкой оператора. Определяются продавец услуги и сторона расчета; зарплата штатного сотрудника не навязывается арендатору.

Новая точка: экономический сценарий, аренда/индексация, инженерные ограничения, оборудование, команда, документы, управляющий, резерв денег и тестовая смена. Готовность подтверждают ответственные. Программа не заменяет осмотр помещения и проверку спроса.

Первая страна Россия. Другие страны получают отдельно проверенные язык, валюту/округление, часовой пояс, продавцов/налоги/кассы, персональные данные и документы. Перевод интерфейса не считается правовой локализацией. Суммы разных валют не складываются без принятой политики.

Приемка ядра: A не видит B; один патч проходит две разные конфигурации; обновление сохраняет данные/брендинг/правила каждого экземпляра; несовместимая копия явно заблокирована для обновления, а не объявлена обновленной. Приемка расширений выполняется только после их включения: стандарты сети, отдельный доход аренды, словарь сравнения филиалов и правильная страна документов.
