# P20 · Развертывание, обновления, резервные копии и поддержка

PROMPT BEGIN P20
Подготовь воспроизводимый запуск SALON OS по выбранным хостингу, географии и режиму салонов. Сначала разработка/staging с демонстрационными данными, затем запуск по уже предоставленной пользователем авторизации. Текущая задача подготовки промптов сама по себе не означает публикацию продукта или подключение реальных клиентов.

Зафиксируй версии, зависимости, окружения, миграции, seed demo, env-схему без секретов, health checks и процедуру первого запуска. Для подтвержденных отдельных веток/копий опиши обновления, версии схемы, совместимость конфигурации и восстановление. Разделяй окружения и секреты каждого салона; сборку артефактов выполняй вне работающего production, если она ухудшает доступность.

Уточни SLO, нагрузку, RPO/RTO, сроки хранения и бюджет. Если неизвестны, предложи измеряемые рабочие цели и обозначь их как проектные. Протестируй типичный каталог/команду/параллельные визиты и реальные устройства; не обещай произвольную масштабируемость без нагрузки. Кеш доступности не подтверждает окончательную запись.

Наблюдаемость: ошибки API, конфликт брони, очередь/задержка/окончательные ошибки уведомлений, подключение, непринятый импорт, расхождение денег, запас/ресурс, потеря подтверждения и места для данных. У каждого рабочего сбоя есть следующий шаг и ответственный. Логи используют идентификаторы/редакцию личных данных по политике.

Резервирование: база, файлы, нужные конфигурации и безопасно хранимые ключи. Расписание копий не заменяет восстановление. Проведи restore в изолированном окружении и измерь целостность/время/потери. Dump не объявляется PITR без фактического механизма. После restore внешние workers выключены до сверки уже отправленных сообщений и иных внешних действий.

Импорт/переключение: владельцы принимают балансы и будущие визиты; команда проходит обучение, тестовую смену и план поддержки. Регламент внешней кассы/терминала и недоступной сети согласован; сотрудники не должны терять обещанные визиты и денежные факты. В кабинете оператора видно состояние версии/интеграций без ненужных клиентских данных.

Приемка: новый разработчик запускает staging по инструкции; обновление не ломает конфигурацию салона; копия реально восстановлена; сбой worker виден и исправим; real SMS не уходят из demo; deploy/rollback не удаляет финансовую историю. Отчет указывает фактически развернутое окружение и непроверенные production-зависимости.
Для подтвержденных forks проверь воспроизводимое создание копии без чужих данных/секретов и применение одного критического исправления к двум различным конфигурациям салонов. Реестр содержит состояние всех версий; несовместимый экземпляр блокируется явно, не объявляется обновленным.
Исходный production-вариант: Timeweb Cloud SPB-3, Docker Compose, reverse proxy с TLS, управляемый PostgreSQL и private S3 в РФ. У каждого сервиса/бэкапа/лога проверить фактический регион; RU-бренд провайдера этого не доказывает. БД не открыта в публичную сеть, TLS автоматически продлевается, диск и очередь наблюдаются. Совместный VPS разных салонов допускается только с изоляцией и зафиксированным риском общего простоя; условия отдельного сервера задаются нагрузкой/SLO. Альтернатива — Selectel в проверенном российском регионе.
ПОСЛЕДНИЕ ОТВЕТЫ ПОЛЬЗОВАТЕЛЯ: сначала бесплатный/дешевый показ клиенту, затем обслуживание в стоимости. Способ бесплатной ссылки пользователь знает и организует сам; не делай выбор demo-хостинга отдельным этапом. Демо работает на вымышленных данных с тестовыми адаптерами. После продажи — российская инфраструктура, реальные провайдеры, резервирование и live-приемка. Себестоимость обслуживания включает инфраструктуру, сообщения, хранение/копии, мониторинг, поддержку и обновления каждой ветки.
