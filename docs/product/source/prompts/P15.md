# P15 · Импорт, интеграции, уведомления и сверка

PROMPT BEGIN P15
Реализуй подключения SALON OS. По ответу пользователя собственная система заменяет CRM. Приоритет — одноразовый управляемый импорт и необходимые уведомления; постоянная двусторонняя синхронизация, платежный gateway и ИИ не входят в первый релиз без новой потребности.

Для каждого адаптера сохрани: provider/version, production host, подтвержденные методы/права, владелец подключения, лимиты, источник истины полей, форматы времени/сумм, гарантии событий, ошибки, reconciliation и mock/test/live. Документация не доказывает выданный партнерский доступ. Не копируй mock-server из документации как production URL и не придумывай подписи webhook.

Импорт: предварительная область, сопоставление полей/единиц, внешний ID в контексте источника, raw-record по допустимой политике, отчет ошибок и версионное правило. Отдельная приемка: люди/семейные контакты, услуги, сотрудники, будущие визиты, история, предоплаты, сертификаты, пакеты, бонусы и запасы. Если сущность не выгружается, покажи это и предложи разрешенный ручной путь. Повторный импорт не создает дубли. Переключение на новую систему имеет дату и запрет двойного редактирования после приемки.

Если CRM-синхронизацию подключают позже, используй ее фактическую семантику. YCLIENTS webhook не гарантирует повтор/порядок/историческое воспроизведение; у Altegio иной retry/id механизм. Периодическая сверка обязательна при ненадежном канале. Лимиты адаптера версионируются и перепроверяются. Все tenants на одном исходящем IP могут делить внешний лимит.

Уведомления: подтверждение контакта, создание/изменение/отмена, подготовка и напоминание. Фиксация визита и задания происходит надежно через outbox. Worker проверяет текущую версию, статус, адресата, канал, цель/разрешение и местное время. Старое напоминание после переноса инвалидируется. Отправка провайдеру, доставка и ответ — отдельные факты; неизвестный результат не скрывается. Не обещай exactly-once внешнюю доставку без контракта.

Очереди имеют lease, ограниченные retries/backoff, дедупликацию, окончательные ошибки, ручную сверку и приоритет интерактивных действий. Секреты хранятся сервером. Пользователь видит «не подключено/настроено/проверено/ошибка», время последнего обмена и ответственного.

Приемка: потерянное событие выявлено сверкой; повтор не откатывает актуальный объект; после падения worker задание не пропало; перенос не отправляет старое время; повтор импорта не меняет контрольные балансы; демо-провайдер не отправляет реальные SMS.
OTP — реальное обязательное подключение для публичной записи. Исходный адаптер SMS.RU: ключ только на сервере, коды ограничены по времени и попыткам, лимиты по номеру/сессии/IP и бюджет отправок, защита от злоупотреблений без раскрытия аккаунтов. Успешная отправка не считается доставкой/подтверждением. OTP не гарантирует сохранение истекшего удержания окна: после проверки атомарно перепроверь доступность. В demo отправка заблокирована; test-коды видны только в изолированном dev-режиме.
