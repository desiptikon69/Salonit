# SalonIt — план универсальной версии

Создан 12 октября 2026 года; состояние сверено 18 октября 2026 года. Исполнение: executing-plans, независимые части делегируются с явным владением файлами. Пользователь поручил выполнить всю работу; дополнительных остановок для утверждения рутинных решений нет. Коммиты, публикация репозитория и подключение реальных данных не входят в автоматически выполняемые действия.

## Цель и актуальный объем

Практически полная универсальная версия SalonIt с редактируемым каталогом волос/ногтей/бровей/макияжа/уходов, серверным учетом и одним общим демонстрационным салоном, затем изолированные копии для заказчиков. Срок не установлен. Все исходные персональные данные вымышлены. Индивидуальные настройки и договоры конкретных салонов заполняются при подключении.

Ответы пользователя заменяют раннее ограничение узким демо P22. ИИ, онлайн-платежи и медицинские функции остаются выключены. Оплата регистрируется как внешний расчет. Домен Timeweb имеется; серверные мощности/доступы из этого не следуют.

## Архитектура

Модульный монолит Next.js App Router, React/TypeScript, Tailwind и Motion. PostgreSQL с Drizzle и параметризованными запросами для атомарных команд; Better Auth для серверных сессий. Отдельные процессы web/worker; transactional outbox. Публичная часть и CRM используют одни правила.

Финансовые суммы — целые копейки; количества материалов — тысячные доли учетной единицы. Снимки цены/длительности/правил сохраняются в визите. Блокировки и ограничение пересечения ресурсов выполняются PostgreSQL. Каждая копия имеет собственную БД и секреты.

## Структура и ответственность

- src/lib/contracts.ts — общие DTO и роли, единый контракт фронтенда/сервера.
- src/server/db.ts, migrations — соединение, Drizzle, SQL-схема.
- src/server/auth.ts, permissions.ts — Better Auth, актор и права.
- src/server/booking.ts, domain/scheduling.ts — ресурсы, этапы, слоты, удержание, подтверждение/перенос.
- src/server/operations.ts, domain/money.ts — выполнение/закрытие, деньги, расход, начисления, остальные команды.
- src/server/queries.ts — проекции по правам, кабинет и показатели.
- src/components/workspace — CRM и формы; src/components/public — сайт, запись, кабинет клиента.
- scripts — миграции, seed/reset, worker, backup/restore и создание копии.
- .github — CI, CodeQL, Dependabot, шаблоны issues/PR и CODEOWNERS.
- tests — денежные/доступ/транзакционные проверки и браузерные сценарии.

## Конкретные проверки

Тесты сначала для существенных доменных операций: 30 конкурентных удержаний одного ресурса → 1 удержание и его подтверждение; конфликт переноса сохраняет старое время; повтор закрытия с разными ключами → 1 набор фактов; одновременное погашение не превышает сертификат; норма 60/факт80 → расход80; версия начисления не меняет прошлое; чужие роли и ID не раскрывают данные. Рутинные стили/конфиг не покрываются зеркальными тестами.

Команды: npm run test; npm run test:integration; npm run typecheck; npm run lint; npm run build; npm run test:e2e. Интеграционные проверки используют отдельную тестовую PostgreSQL. До выполнения каждого шага проверять, что команда существует и окружение готово.

План браузерной приемки: desktop и телефон, guest booking→OTP→кабинет, admin→приход→master→факт→close→начисление/отчет, reload, конфликт, ошибки сети, клавиатура/reduced-motion. Имеющиеся снимки находятся в artifacts. В наборе 15 модульных проверок и 5 браузерных сценариев journeys, а также отдельный браузерный сценарий клиентского доступа; браузерный путь закрытия включает частичную отмену и повторное добавление услуги. Полный перечень выше остается целевой проверкой и не означает, что каждый сценарий уже пройден. Текущий запуск и его результаты фиксируются отдельно, без автоматической отметки всех пунктов.

## Обязательные пределы

Не изображать внешние SMS/банк/ККТ как подключенные. Не заявлять о публичном развертывании без фактической проверки. Цены — выбранные ориентиры по источникам; формулы/расходы — демонстрационные предположения. Все значимые ограничения и невыполненные сценарии фиксируются в progress, без отметки «полная готовность» за наличие экранов.
