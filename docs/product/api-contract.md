# Контракт реализации SalonIt

Общие DTO: src/lib/contracts.ts. Деньги minor (копейки), материалы quantityMilli (1000 = одна учетная единица). Даты ISO. Запросы JSON, ошибка { error: string, code?: string }, успех объект данных.

GET /api/catalog -> CatalogData (публичный). GET /api/workspace?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD -> WorkspaceState (сотрудник, с фильтрацией по роли; период доступен owner/accountant). GET /api/portal -> PortalState (собственный клиентский аккаунт). GET /api/export?entity=clients|visits|materials|expenses|accruals -> CSV с ролевыми ограничениями и экранированием формул. POST /api/demo/login {role} -> {ok:true}, устанавливает cookie; только APP_MODE=demo. POST /api/logout -> {ok:true}.

GET /api/booking/slots?date=YYYY-MM-DD&services=id1,id2&mode=parallel|sequential&staffId=optional&visitId=optional -> {slots: Slot[]}.
POST /api/booking/hold {serviceIds:string[],mode,startAt,staffId?,name,phone} -> {holdId,holdToken,expiresAt,totalMinor}.
POST /api/booking/otp {phone} -> {ok:true,demoCode?:string}; код создан настоящим OTP-механизмом, demoCode виден только в demo.
POST /api/booking/confirm {holdId,holdToken,phone,code,accessKey?} -> {visit,accessKey?}; ставит сессию клиента и HttpOnly-cookie доверенного устройства. Первый личный ключ возвращается однократно. Существующий телефонный аккаунт требует доверенное устройство либо правильный accessKey до проверки OTP; нативные телефонные маршруты Better Auth заблокированы от обхода этого правила. Ключи и токены устройств сохраняются только как хеши.

POST /api/commands {action:string,payload:object,commandId:string} -> {ok:true,result?:unknown}. Команда создает UUID в UI; ошибку показывать, после успеха перечитывать данные. Все проверки ролей/состояний на сервере.

Команды:
- visit.status {id,status,version?}; visit.materials {id,materials:Usage[],version}; visit.close {id,version,payments:PaymentInput[],materials?:Usage[],discountMinor?:number}; visit.move {id,startAt,version}; visit.refund {id,amountMinor,reason}; visit.rework {id,startAt,reason}; visit.payment {id,version?,amountMinor,method:"cash"|"card"|"sbp"}.
- visit.addService {id,version,serviceId,staffId?,startAt?,reason}; visit.item.cancel {id,version,itemId,reason}. Только owner/admin. Добавление — последовательное, в тот же день, после существующих услуг и буферов, максимум шесть активных позиций; сервер заново проверяет ресурсы/мастера и занятость клиента. При добавлении после сохранения факта расхода закрытие требует его повторного подтверждения администратором. Частичная отмена доступна только для неначатой позиции при наличии сохраненных reservations у остальных; общий факт расхода/факт данного мастера блокирует отмену, последняя позиция отменяется через весь визит. История отмененной позиции сохраняется, ее цена/нормы/начисление исключаются.
- service.save {id?,...Service}; staff.save {id?,...Staff}; resource.save {id?,...Resource}; client.save {id?,...Client}.
- material.save {id?,...Material}; stock.receive {materialId,quantityMilli,costMinor}; stock.adjust {materialId,quantityMilli,reason}; purchase.save {id?,...Purchase}; purchase.receive {id}.
- expense.save {id?,...Expense}; certificate.issue {clientId,nominalMinor,saleMinor,kind?,unitsRemaining?,serviceIds?}; payroll.approve {month:"YYYY-MM"}; payroll.pay {month}.
- payroll.rule.create (синоним payroll.rule.save) {staffId,effectiveFrom,commissionBps,fixedMinor,guaranteeMinor,guaranteeScope:"total"|"variable",reason}. Только owner; добавляется новая неизменяемая версия. Фиксированная часть и гарант меняются с первого числа месяца. Новая версия не может затронуть уже выполненную услугу/начисление или утвержденные месячные условия. При фактическом завершении сервер сохраняет completedAt, rewardRuleId и rewardRuleSnapshot; начисление относится к месяцу события по Москве. Legacy-позиции без completedAt используют исходную ставку бронирования и плановое endAt с признаком legacy.
- resource.process {id,event:"used"|"start"|"cleaned"|"sterilized"|"control_pass"|"control_fail"}. Только owner/admin/stock, типы tools-hands/tools-feet. Последовательность: ready → dirty → cleaning → sterilizing → control → ready; провал контроля возвращает dirty. Завершение услуги помечает использованный инструмент dirty автоматически. Обработка недоступна во время использования, начало услуги требует ready. События сохраняются в resource_cycle.
- finance.correction.create {sourceVisitId,sourceAccrualId?,target:"revenue"|"materials"|"expenses"|"payroll",deltaMinor,postingDate,reason}; finance.correction.approve {id,version}; finance.correction.payout {id,version,method:"cash"|"card"|"sbp",externalReference}. Только owner/accountant. Источник — закрытый визит; для payroll требуется принадлежащее ему начисление. Ненулевая знаковая сумма, причина от трех символов и дата текущего открытого месяца не позднее сегодня. Создание, согласование и выплата — разные добавляемые факты; исходные строки не переписываются. Выплачивается только согласованная положительная payroll-корректировка; отрицательная помечается для рассмотрения взаиморасчета без автоматического удержания.
- client.access.reset {clientId,evidence,reason}. Только owner/admin; evidence и reason от десяти символов. Требуется согласованная связь карточки и телефонного аккаунта. Отзывает сессии и доверенные устройства, выдает новый accessKey однократно; повтор команды возвращает {clientId,reset:true,replayed:true} без ключа. Это восстановление личного ключа, смены номера команда не делает.
- task.save {id?,...Task}; complaint.save {id?,...Complaint}; shift.save {id?,...Shift}; notification.create {clientId,purpose,name}; settings.save {name,address,phone,hours,...}.
- import.preview {csv:string} -> {rows,errors,fingerprint}; import.commit {csv:string}; demo.reset {} (owner only); installation.save {id?,...Installation}.

Перенос через клиентский кабинет допускает только собственный визит и status confirmed. Сотрудник master видит/меняет только свои назначения и расход по ним; расчеты закрывает admin/owner. Финансовые отчеты owner/accountant: потоки фильтруются по учетной дате, долг и обязательства сертификатов — текущие остатки всей установки. Склад доступен owner/stock, настройки — owner, оператору — только реестр и технический health.

Основные SQL-таблицы: records(id text PK,kind text,data jsonb,created_at timestamptz,updated_at timestamptz) — услуги/команда/клиенты/материалы/задачи и др.; appointments(id uuid PK,reference text,client_id text,status text,start_at,end_at,items jsonb,total_minor bigint,paid_minor bigint,materials jsonb,version int,receipt_status text,note text,closed_at,hold_token_hash text,hold_phone text,hold_expires_at,parent_id uuid); allocations(id uuid,appointment_id uuid,resource_key text,start_at,end_at,active bool) + gist exclusion.
payments(id uuid,visit_id uuid,method text,amount_minor bigint,kind text,certificate_id text,created_at), consumptions(id uuid,visit_id uuid,material_id text,quantity_milli bigint,cost_minor bigint,created_at, UNIQUE visit_id/material_id), accruals(id uuid,visit_id uuid,staff_id text,service_name text,base_minor bigint,amount_minor bigint,rate_bps int,status text,date date,rule_snapshot jsonb,UNIQUE visit_id/staff_id/service_name), payouts(id uuid,month text,staff_id text,amount_minor bigint,UNIQUE month/staff_id), audit_events(id uuid,actor text,action text,entity_id text,details jsonb,created_at), outbox(id uuid,kind text,payload jsonb,status text,created_at), commands(id text PK,actor_id text,action text,result jsonb,created_at), import_runs(fingerprint text PK,result jsonb,created_at).

db.ts exports pool, db(Drizzle), type SqlClient, rows<T>(sql,values?,client?), first<T>(...), transaction(fn). rows returns native snake_case SQL keys. records.data хранит CAMELCASE DTO без id (id из столбца). records helper exports listRecords<T>(kind,client?), getRecord<T>(kind,id,client?,lock=false), saveRecord(kind,id,data,client), audit(client,actor,action,entityId,details). getRecord/listRecords возвращают {id,...data}.
errors.ts exports AppError(status,message,code?), requireCondition(condition,status,message).
permissions.ts exports authorize(actor,roles), canManageVisit(actor,visit).

operations.ts exports runOperation(actor:Actor,action:string,payload:unknown,commandId:string):Promise<unknown>; маршрут направляет visit.move/visit.rework/visit.addService в runBookingCommand, finance.correction.* в runFinancialCorrection, client.access.reset в runClientAccessCommand; demo.reset отдельно. Модуль операций разбирает payload через Zod и результаты SQL через rows. commands idempotency под actor_id + action; бизнес-state дополнительно. Это описание текущих таблиц и модулей, а не обещание публичной совместимости API; полнота приемки отражена в implementation-status.md.
