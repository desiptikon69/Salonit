# Публикация SalonIt на Timeweb и установка на телефон

Обновлено 19 октября 2026 года.

Приложение уже собирается в production-режиме и умеет устанавливаться на домашний экран:
есть web app manifest, PNG- и maskable-иконки, splash-экраны iOS, service worker,
офлайн-страница и установочная подсказка. Для установки нужен **HTTPS-домен** —
бесплатный технический домен Timeweb подходит.

## Что понадобится

- аккаунт **Timeweb Cloud** (не обычный shared-хостинг);
- свободный технический домен Timeweb: `.tw1.su`, `.tw1.ru`, `.webtm.ru` или `.twc1.net`;
- PostgreSQL 17;
- один из двух вариантов размещения:
  - **App Platform** — Timeweb сам собирает Dockerfile и выдаёт домен с SSL;
  - **Облачный сервер (VPS)** — Docker Compose, Caddy и постоянный диск с базой.

Shared-хостинг Timeweb для этого приложения не подходит: ему нужны Node.js 24
и постоянный процесс с PostgreSQL. Если домен уже привязан к «Хостингу сайтов»,
перепривяжите его к App Platform или к облачному серверу.

> **Важно про данные.** Сейчас приложение работает в демонстрационном режиме:
> вход по SMS имитируется, реальной отправки кодов нет. Не принимайте реальные
> персональные данные и реальные записи до подключения SMS-провайдера и рабочего
> режима. Для показа приложения и установки на телефон демо-режим подходит.

## Короткий чек-лист для App Platform

1. Создать **пустой** репозиторий GitHub и отправить проект.
2. Создать приватную сеть, затем PostgreSQL **в этой сети**, скопировать строку подключения.
3. App Platform: фреймворк **Dockerfile**, health path `/api/health`, та же
   приватная сеть, переменные окружения.
4. Запустить деплой и дождаться миграций и демо-данных.
5. Привязать домен, задать `BETTER_AUTH_URL`, перезапустить деплой.
6. Проверить `/api/health`, `/api/ready` и установить приложение на телефон.

Шаблон переменных: [deploy/app-platform.env.example](../deploy/app-platform.env.example).

## Переменные окружения

| Переменная | Обязательна | Значение |
| --- | --- | --- |
| `DATABASE_URL` | да | `postgresql://salonit:ПАРОЛЬ@ХОСТ:5432/salonit` |
| `BETTER_AUTH_URL` | да | точный адрес с `https://`, без слэша на конце |
| `BETTER_AUTH_SECRET` | да | случайная строка, например `openssl rand -hex 48` |
| `APP_MODE` | да | `demo` для показа, `live` для рабочего запуска |
| `INSTALLATION_ID` | да | 3–80 латинских букв, цифр, `_` или `-` |
| `DEMO_PASSWORD` | для demo | пароль демонстрационных сотрудников |
| `SEED_DEMO` | нет | `1` — создать демо-данные при первом запуске |
| `RUN_MIGRATIONS` | нет | `1` (по умолчанию) — применить миграции при старте |
| `TZ` | нет | `Europe/Moscow` |

Пароль в `DATABASE_URL` должен быть URL-совместимым. Надёжнее всего использовать
hex-пароль: `openssl rand -hex 16`.

## Вариант A. App Platform + управляемый PostgreSQL

Это самый быстрый путь: Timeweb собирает [Dockerfile](../Dockerfile), запускает
контейнер и выдаёт технический домен с сертификатом Let's Encrypt.

### 1. Положите проект в Git-репозиторий

App Platform подключает GitHub, GitLab или Bitbucket. В этой папке уже
создан первый коммит; осталось отправить проект в пустой репозиторий:

```powershell
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/salonit.git
git push -u origin main
```

Если проект до этого не был Git-репозиторием, сначала выполните
`git add .` и `git commit -m "SalonIt: production build with PWA"`.
Файл `.env` в репозиторий не попадёт: он исключён через `.gitignore` и
`.dockerignore`.

### 2. Создайте PostgreSQL

В Timeweb Cloud: **Облачные базы данных → PostgreSQL**. Выберите регион, тариф
и версию 17. После создания скопируйте строку подключения со вкладки
**«Подключение»**.

Желательно добавить будущее приложение и базу в одну **приватную сеть**:
тогда `DATABASE_URL` использует приватный адрес базы, а не публичный.

Порядок важен: сначала создайте сеть в **«Сети» → «Приватные сети»**, затем
создайте базу уже в этой сети и при создании приложения выберите её же.
В App Platform нельзя сменить приватную сеть после деплоя. Если приложение
уже создано без сети, используйте публичный IP базы и ограничьте доступ по
IP приложения (он виден на вкладке «Дашборд»).

Если база требует TLS, а её сертификат не входит в системное хранилище,
добавьте к строке подключения `?sslmode=no-verify` (шифрование без проверки
сертификата) или настройте `sslrootcert` с сертификатом Timeweb. Для приватной
сети обычно достаточно строки, которую показывает панель.

### 3. Создайте приложение

1. **App Platform → Создать**.
2. Подключите репозиторий и нужную ветку.
3. В поле «Фреймворк» выберите **Dockerfile**.
4. Регион — Санкт-Петербург (или ближайший доступный).
5. Конфигурация — минимум 1 CPU / 1 ГБ RAM; для сборки Next.js лучше 2 ГБ.
6. В расширенных настройках укажите **путь проверки состояния**:
   `/api/health` — это проверка живости, она специально не зависит от
   PostgreSQL, чтобы платформа не перезапускала контейнер при коротком сбое
   базы. Для мониторинга готовности базы есть `/api/ready` (503, пока база
   недоступна).
7. Добавьте переменные из таблицы выше. Для первого запуска:

```text
APP_MODE=demo
SEED_DEMO=1
RUN_MIGRATIONS=1
DEMO_PASSWORD=<случайный пароль>
BETTER_AUTH_SECRET=<openssl rand -hex 48>
INSTALLATION_ID=salonit-main
```

8. Нажмите **«Запустить деплой»**.

При старте контейнер сам ждёт базу, применяет миграции, один раз создаёт
демо-данные (повторный запуск их не дублирует) и запускает Next.js на порту
3000. Логи видны на вкладке **«Деплой»**.

### 4. Домен

У приложения на вкладке **«Дашборд»** уже будет бесплатный технический домен
вида `xxxxx.twc1.net` с SSL. Его можно использовать сразу.

Если нужен другой бесплатный домен, добавьте его в **«Домены и SSL» →
«Добавить домен»**, выберите зону `.tw1.su`, `.tw1.ru`, `.webtm.ru` или
`.twc1.net` и привяжите к приложению: **Настройки → Домены → Редактировать**.
Привязка и отвязка домена автоматически запускают повторный деплой.

После того как домен известен, обязательно задайте:

```text
BETTER_AUTH_URL=https://ВАШ-ДОМЕН
```

без слэша на конце. Если переменная была задана неверно, вход и cookie будут
работать неправильно. После изменения переменной перезапустите приложение
(кнопка повторного деплоя или «Перезапустить»).

### 5. Проверка

```text
https://ВАШ-ДОМЕН/api/health          → {"status":"ok","database":"ok"}
https://ВАШ-ДОМЕН/api/ready           → {"status":"ready"}
https://ВАШ-ДОМЕН/manifest.webmanifest
https://ВАШ-ДОМЕН/sw.js
https://ВАШ-ДОМЕН/offline
```

Откройте сайт на телефоне. Через несколько секунд появится подсказка
«SalonIt на главном экране». На Android она может предложить кнопку
**«Установить»**, на iPhone — инструкцию «Поделиться → На экран „Домой“».

## Вариант B. Облачный сервер + Docker Compose

Этот путь даёт постоянный диск с базой, полный контроль и не зависит от
сборки в App Platform. Нужен VPS с Docker; подойдёт 2 CPU / 2 ГБ RAM.

Файлы для сервера уже лежат в каталоге [`deploy`](../deploy):
`docker-compose.yml`, `Caddyfile`, `.env.example` и `entrypoint.sh`.

### 1. Создайте сервер

В Timeweb Cloud: **Облачные серверы → Создать**. Ubuntu 24.04, 2 ГБ RAM,
публичный IP, SSH-ключ. Откройте входящие порты **22, 80, 443**.

### 2. Привяжите бесплатный домен

**Домены и SSL → Добавить домен** → выберите бесплатную зону
(`.tw1.su`, `.tw1.ru`, `.webtm.ru`, `.twc1.net`) → укажите
**«Облачный сервер»** и нужный сервер. DNS-записи Timeweb настроит сам;
подождите обновления DNS (обычно 5–15 минут).

### 3. Установите Docker

```bash
ssh root@IP_СЕРВЕРА
apt update
apt install -y git
curl -fsSL https://get.docker.com | sh
```

### 4. Загрузите проект

Вариант с Git:

```bash
git clone https://github.com/ВАШ_АККАУНТ/salonit.git /opt/salonit
```

Либо загрузите архив `salonit-timeweb-deploy.zip` с компьютера:

```powershell
scp .\salonit-timeweb-deploy.zip root@IP_СЕРВЕРА:/opt/
```

```bash
cd /opt
apt install -y unzip
unzip salonit-timeweb-deploy.zip
```

### 5. Заполните настройки

```bash
cd /opt/salonit/deploy
cp .env.example .env
nano .env
```

Минимум, что нужно заменить:

```text
DOMAIN=salonit.tw1.su
BETTER_AUTH_URL=https://salonit.tw1.su
POSTGRES_PASSWORD=<openssl rand -hex 16>
BETTER_AUTH_SECRET=<openssl rand -hex 48>
DEMO_PASSWORD=<пароль для демо-сотрудников>
```

Секреты можно сгенерировать прямо на сервере:

```bash
openssl rand -hex 16
openssl rand -hex 48
```

### 6. Запустите

```bash
docker compose up -d --build
docker compose logs -f app caddy
```

Первый запуск занимает несколько минут: собирается Next.js, затем контейнер
ждёт PostgreSQL, применяет миграции, создаёт демо-данные и поднимает сервер.
Caddy получает сертификат Let's Encrypt для `DOMAIN` автоматически.

Проверьте:

```bash
curl https://ВАШ-ДОМЕН/api/health
curl -I https://ВАШ-ДОМЕН/sw.js
docker compose ps
```

### 7. Обновления, логи и резервная копия

```bash
cd /opt/salonit
git pull
cd deploy
docker compose up -d --build

docker compose logs -f app
docker compose exec -T db pg_dump -U salonit -Fc salonit > /root/salonit-$(date +%F).dump
```

Архив базы храните вне сервера, в зашифрованном виде. Проверяйте восстановление
в отдельную пустую базу, а не в рабочую.

## Установка на телефон и «незаметность» сайта

Что уже делает приложение:

- `display: standalone` — после установки нет адресной строки и вкладок браузера;
- `theme-color` совпадает с фоном интерфейса, поэтому строка состояния не
  выбивается из дизайна;
- splash-экраны iOS показывают фирменную заставку вместо белой вспышки;
- maskable-иконки корректно обрезаются под форму иконки на Android;
- service worker кэширует статику, поэтому повторный запуск быстрый;
- офлайн-страница объясняет отсутствие сети;
- нижняя навигация учитывает `env(safe-area-inset-bottom)` на iPhone.

### Android / Chrome

1. Откройте сайт по HTTPS.
2. Через несколько секунд появится подсказка «SalonIt на главном экране».
3. Нажмите **«Установить»**. Если кнопки нет — меню ⋮ →
   **«Установить приложение»** или **«Добавить на главный экран»**.

### iPhone / Safari

1. Откройте сайт именно в **Safari**.
2. Кнопка «Поделиться» → **«На экран „Домой“»**.
3. Нажмите «Добавить». Иконка появится на домашнем экране; при запуске
   откроется полноэкранное приложение с заставкой.

На iOS установка из Chrome/Firefox может вести себя иначе — Safari надёжнее.
Установка доступна только по HTTPS.

### Компьютер

Chrome/Edge: иконка установки в адресной строке или меню → «Установить SalonIt».

## Проверка PWA после публикации

1. **Chrome DevTools → Application → Manifest**: имя, иконки, `display:
   standalone`, start URL.
2. **Application → Service Workers**: статус `activated`, scope `/`.
3. **Application → Cache Storage**: есть `salonit-...-static`.
4. Отключите сеть в DevTools и обновите страницу — должна открыться
   офлайн-страница, а не ошибка браузера.
5. **Lighthouse → категория PWA**: установка и offline-проверки.

Быстрая проверка через терминал:

```powershell
Invoke-RestMethod https://ВАШ-ДОМЕН/api/health
Invoke-RestMethod https://ВАШ-ДОМЕН/manifest.webmanifest
Invoke-WebRequest https://ВАШ-ДОМЕН/sw.js -Method Head
```

## Обновление установленного приложения

После нового деплоя service worker скачивает новую версию. Она активируется,
когда закрыты все вкладки приложения; при следующем запуске открывается уже
новая версия. Это сделано специально, чтобы обновление не сбрасывало
заполненную форму записи. Если нужно проверить новую версию сразу — закройте
PWA полностью (свайп из списка задач) и откройте снова.

## Рабочий режим вместо демо

Демо-режим нужен для показа. Для реальных клиентов:

1. Поставьте `APP_MODE=live`, `SEED_DEMO=0`, уберите `DEMO_PASSWORD`.
2. Подключите SMS-провайдера и проверьте вход по телефону — без него запись
   клиентов в live-режиме завершится ошибкой 503.
3. На чистой базе выполните инициализацию:

```bash
cd /opt/salonit/deploy
docker compose --profile tools run --rm init
```

4. Создайте владельца:

```bash
docker compose --profile tools run --rm \
  -e SALONIT_USER_PASSWORD='надёжный-пароль' \
  user-create owner@example.org "Имя владельца" owner
```

5. Войдите через `/login`, заполните контакты, расписание, услуги и только
   после проверки включайте услуги.

Для App Platform шаги 3–4 выполняются из локального терминала с `DATABASE_URL`
удалённой базы (`npm run installation:init`, `npm run user:create -- ...`),
если у приложения нет консоли.

## Частые проблемы

**Приложение не стартует, в логах «Database did not become ready»**
Проверьте `DATABASE_URL`, доступность базы из контейнера и приватную сеть.
В App Platform добавьте приложение и базу в одну сеть.

**Ошибка сертификата PostgreSQL**
Уберите проверку CA для приватного соединения: `?sslmode=no-verify`, либо
укажите `sslrootcert` с сертификатом Timeweb. Не отключайте TLS в публичной сети.

**Вход не работает, cookie не сохраняются**
`BETTER_AUTH_URL` должен точно совпадать с адресом в браузере: `https://`,
без слэша на конце, без `www`, если сайт открыт без `www`. После изменения
перезапустите приложение.

**Нет кнопки установки на Android**
Нужен HTTPS, manifest и service worker. Подсказка появляется после нескольких
секунд; если браузер не показывает установку, используйте меню ⋮. На iPhone
кнопки установки в интерфейсе нет — только «Поделиться → На экран „Домой“».

**Установлено старое оформление**
Закройте все вкладки/PWA, откройте заново. Service worker обновляется при
следующем запуске. Жёсткая перезагрузка: DevTools → Application → Clear site data.

**Caddy не получает сертификат**
Проверьте, что домен привязан к этому серверу, A-запись указывает на его IP,
порты 80 и 443 открыты, а `DOMAIN` в `deploy/.env` совпадает с доменом.
Технические зоны Timeweb не позволяют менять DNS вручную — привязка к серверу
должна быть выполнена в панели.

**«Неверный логин» у демо-сотрудников**
Пароль задаётся в `DEMO_PASSWORD` до первого создания демо-данных. Если база
уже заполнена, изменение переменной не меняет старый пароль; для чистой
демонстрации пересоздайте базу или используйте `db:reset` только на локальной
демо-базе.

## Что не входит в этот запуск

- реальная SMS-доставка;
- онлайн-платежи (оплаты фиксируются вручную);
- приём реальных персональных данных до настройки доступа и согласий;
- автоматическое резервное копирование managed-базы средствами Timeweb.

Перед рабочим запуском проверьте резервное копирование и восстановление,
договоры с провайдерами и уведомление об обработке персональных данных.
