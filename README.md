# SalonIt

Универсальное веб-приложение для салона: публичный каталог, запись, кабинет клиента и рабочие места сотрудников. Общая версия служит основой для отдельных копий салонов. Исходное техническое задание перенесено полностью; реализация и проверка продолжаются. Демо-версия опубликована, но приложение не готово принимать реальные персональные данные.

Стек: Node.js 24, Next.js 16, React 19, TypeScript, PostgreSQL, Better Auth. Версии зафиксированы в package-lock.json. Локальный запуск использует обычный процесс PostgreSQL, без контейнеров.

## Онлайн-демо

Бесплатный стенд: [https://salonit.vercel.app](https://salonit.vercel.app) — Vercel Hobby + Neon Free, установка на домашний экран работает. Это демонстрационный режим: реальная SMS-доставка не подключена, реальных клиентов и персональные данные туда отправлять нельзя. Подробности — в [инструкции по бесплатной публикации](docs/deploy-free.md).

## Локальное демо

1. Установите Node.js 24 и выполните `npm ci`.
2. Если `.env` еще нет, скопируйте `.env.example` в `.env`. Не перезаписывайте существующие настройки. Замените `BETTER_AUTH_SECRET` и `DEMO_PASSWORD` случайными значениями. Для каждого можно получить значение командой `node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"`.
3. В отдельном терминале запустите `npx tsx scripts/local-db.ts` и дождитесь сообщения о готовности. База хранится в `.data/postgres`; терминал оставьте открытым.
4. Выполните `npm run setup`, затем `npm run dev`.
5. Откройте [SalonIt](http://localhost:3000). Используйте только вымышленные данные.

Фоновая обработка запускается отдельно: `npm run worker`. Она обрабатывает удержания и очередь уведомлений; в демо сообщения помечены как имитация.

Параметры базы из `.env.example` подходят только для локального демо. `db:seed` добавляет демонстрационный набор; `db:reset` удаляет данные выбранной демонстрационной базы и создает набор заново. Не запускайте сброс в среде с нужными данными.

## Приложение на телефоне

SalonIt — устанавливаемое PWA: manifest, иконки, splash-экраны, service worker и офлайн-страница уже в проекте. По HTTPS сайт открывается без адресной строки после добавления на домашний экран: Android — «Установить приложение», iPhone — «Поделиться → На экран „Домой“». Публикация на бесплатном домене Timeweb и проверка установки описаны в [инструкции для Timeweb](docs/deploy-timeweb.md).

## Проверки

```text
npm run typecheck
npm run lint
npm test
npx tsx scripts/check-integration.ts
npm run build
npm run test:e2e
```

Интеграционный запуск проверяет `TEST_DATABASE_URL`, применяет миграции только к базе с точным именем `salonit_test`, затем запускает тесты. Эти тесты очищают таблицы. Для них всегда нужна отдельная база; `DATABASE_URL` не используется как запасной адрес. Перечень команд здесь не является отчетом об их успешном выполнении.

Демонстрационные входы и вывод кода подтверждения предназначены только для `APP_MODE=demo`. Вход сотрудников по почте и паролю реализован. Чистая установка: `npm run installation:init`; создание сотрудника: `npm run user:create -- <email> <имя> <роль> [staffId]` с паролем в переменной `SALONIT_USER_PASSWORD`. Подробности и ограничения — в инструкции развертывания. Реальная SMS-доставка и платежный шлюз не подключены. Также нужно настроить внешние службы, домен, защиту и восстановление резервной копии. Проверки GitHub начинают работать только после размещения репозитория на GitHub; публикация автоматически не выполняется.

К существующему клиентскому аккаунту с нового устройства нужен личный ключ доступа вместе с кодом подтверждения. Восстановление ключа выполняет владелец или администратор после проверки владельца аккаунта; прежние сессии и доверенные устройства отзываются. Автоматического объединения карточек по телефону нет.

В открытом визите доступны добавление услуги с повторной проверкой ресурсов и отмена еще не начатой позиции. Условия начисления фиксируются при фактическом завершении услуги; изменения закрытых фактов оформляются отдельными согласуемыми корректировками. Универсальная версия еще не завершена: импорт ограничен клиентами, бонусного реестра нет, восстановление резервной копии и независимость двух развернутых установок практически не проверены. Подробнее — в матрице приемки.
